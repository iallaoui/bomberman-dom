# bomberman-dom

A 2–4 player Bomberman-style game rendered with normal DOM elements and the included mini-framework. The browser client uses the framework for virtual DOM rendering, state, delegated events, and hash-based routing. A small Node server uses WebSockets for the lobby, chat, authoritative game simulation, and synchronization.

The project does not use React, Vue, Canvas, or WebGL. Its only package dependency is `ws`, used by Node for the WebSocket server.

## Run

```sh
npm install
npm start
```

Open `http://localhost:8086` in two to four tabs or browser windows. Each tab has its own connection and player, and each player must choose a different nickname.

When changing browser code, hard-refresh the page.

## Controls

- Move: arrow keys or WASD
- Place bomb: Space
- Chat: use the chat field in the waiting room or during a match

## Match flow

- Two players start a 20-second waiting period followed by a 10-second countdown.
- Four players skip directly to the 10-second countdown.
- Every player starts in a different corner with three lives.
- The last active player wins. The server returns connected players to the waiting room after the result screen.

## Game rules

- Gray walls are permanent.
- Brown blocks are randomly generated by the server and can be destroyed.
- Bomb explosions travel in four directions and stop at walls or the first block.
- Destroyed blocks may reveal one of three power-ups:
  - `B`: one extra simultaneous bomb
  - `F`: one extra tile of flame range
  - `S`: increased movement speed
- A blast removes one life. Players respawn briefly invulnerable until all three lives are gone.

## Architecture

```text
frontend/
  index.html          browser entry
  app.js              small application coordinator
  components/         shared chat UI
  screens/            join/lobby UI, game UI, input, and interpolation
  style.css           fixed-board and interface styles
  mini-framework/     DOM diffing, state, events, and routing
  network/            per-tab browser WebSocket connection
backend/
  index.js            HTTP, WebSocket, lobby, and chat server
  game.js             authoritative game rules and simulation
```

The server simulates movement at 60 ticks per second and sends snapshots at about 20 updates per second. It is authoritative: clients send input, but the server decides positions and game outcomes.

The client uses `requestAnimationFrame` only while interpolating player movement or applying pending UI work. A tiny transform-only CSS indicator animates continuously while the game screen is open to satisfy the continuous-animation requirement without an always-running JavaScript loop. It is sampled at the display's refresh rate, but it does not guarantee or measure a particular FPS.

The client re-renders only structural changes such as bombs, explosions, power-ups, damage, and results. Player transforms are updated directly between structural renders. The server sends the map only at match start and after a block changes.

The server retains the latest 60 chat messages in memory. Chat history is cleared when the Node process restarts, and disconnected players are removed immediately.

## Audit notes

- The whole 15×13 map is visible at once.
- Every spawn has two clear three-tile escape corridors, longer than the initial flame range.
- Nicknames and chat are rendered as text nodes rather than HTML.
- The server, rather than clients, decides collisions, damage, destroyed blocks, power-ups, and the winner.
- Late players cannot join a match already in progress.
